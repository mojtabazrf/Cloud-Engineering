## Introducing Today's Project!

### What is Amazon VPC?

Amazon VPC is a logically isolated virtual network in AWS where we can launch and manage resources such as EC2 instances, and it is useful because it allows us to control IP address ranges, subnets, route tables, and network security, while enabling secure communication between resources within and across VPCs.

### How I used Amazon VPC in this project

In today's project, I used Amazon VPC to create two isolated virtual networks, establish a VPC peering connection between them, configure route tables to enable private communication between EC2 instances, and use VPC Flow Logs and CloudWatch Logs Insights to monitor and analyze network traffic.

### One thing I didn't expect in this project was...

One thing I didn't expect in this project was that my EC2 instances could communicate using their public IP addresses while communication through their private IP addresses failed because the route tables were missing routes to the VPC peering connection. This helped me understand how important route table configuration is for private communication between VPCs.

I created an IAM policy because VPC Flow Logs needs specific permissions to publish network traffic logs to CloudWatch Logs, and the policy defines which actions the service is allowed to perform on the required resources.

I also created an IAM role because it allows the VPC Flow Logs service to assume the role and obtain the permissions defined in the attached IAM policy, enabling it to publish log data to CloudWatch Logs securely without requiring long-term credentials.

## Analyzing flow logs

Flow logs tell us about the source and destination IP addresses, source and destination ports, network protocol, number of packets and bytes transferred, traffic acceptance or rejection status, and the time the traffic was observed. These details help us monitor network activity, troubleshoot connectivity issues, and investigate potential security threats.

For example, the flow log I've captured tells us that an instance with the private IP address 10.1.0.204 communicated with the IP address 18.206.107.28 over TCP (protocol 6), using destination port 22 (SSH) and source port 49388. The traffic was accepted, and 2 packets totaling 176 bytes were recorded during the flow's observation period.

![Image](https://nextwork.ai/lively_brown_mysterious_lion/uploads/6954a600-a89e-56b0-886b-7054da118a3b_d116818e)

## Logs Insights

Logs Insights is a feature in Amazon CloudWatch that allows us to interactively query, analyze, and visualize log data using a query language to identify patterns, troubleshoot issues, and investigate network activity.

I ran the query:

stats sum(bytes) as bytesTransferred by srcAddr, dstAddr
| sort bytesTransferred desc
| limit 10

This query analyzes the total amount of network traffic transferred between each source and destination IP address, sorts the results in descending order by the number of bytes transferred, and displays the top 10 pairs with the highest traffic volume.
